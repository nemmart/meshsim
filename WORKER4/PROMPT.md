# Worker 4: meshsim to v1.2

You are bringing meshsim, the cycle-level simulator of the mesh (part of an ASIC for proving the Jolt zkVM),
from the v1.1 machine to the v1.2 design. The v1.2 design exists only as a decisions log so far; the spec
(`wip/spec/machine-spec.md`) is still v1.1. meshsim is the first thing to move: the sort (WORKER5) and the
replayer (WORKER6) are ported onto your simulator once its core is in place.

REPOSITORY
- Clone https://github.com/nemmart/meshsim with the meshsim token from your user preferences (as
  `https://x-access-token:<token>@github.com/nemmart/meshsim.git`). Never write a token into a file.
- `wip/` is the work in progress; `v1.0/` and `v1.1/` are frozen. Work on a branch, **`v1.2-meshsim`**, push
  often, and leave merging into `main` to the owner and the integrator.
- For long runs, the Quest runner can run tasks in parallel: its repository and `PIPELINE.md` are in your user
  preferences. It cannot reach meshsim, so a task carries the code it needs.

INPUTS
- **`wip/planning/DECISIONS-v1.2.md`: the design.** Read "Where the design stands", then every section.
  Later sections revise earlier ones and superseded points are marked; when two places disagree, the later
  section wins. Sections 32 (the integrator's calls) and 33 (deferred) say what is settled for implementation
  and what is not.
- `wip/spec/machine-spec.md` (v1.1): the authority for everything the log doesn't change.
- `wip/meshsim/`: the simulator (`src/`, 40 classes), its suites (`test/`), its software (`sw/`: `mesh.h`
  generated by `Registers.java`, `crt0.S`, the loader, `tests/`, `replay/`, `ext/`), and `README.md`.
- `WORKER3/REVIEW-2.md`, section 6: the migration inventory, file by file. Use it as your checklist, corrected
  by 31 and 36: `loader.S` goes (the boot ROM replaces it), and staging is counted.
- `WORKER1/`, `WORKER2/`, `WORKER3/` reviews, for the reasoning behind decisions.

YOUR SCOPE
- **Yours:** `wip/meshsim/src/`, `wip/meshsim/test/`, `wip/meshsim/sw/` except `sw/ext/` and `sw/replay/`,
  the generated `mesh.h` and `REGISTERS.md`, `run_tests.sh`, and a new boot ROM image.
- **Not yours:** `wip/sort/` and `wip/meshsim/sw/ext/` (WORKER5); the replayer's software and its tile-side
  behaviour beyond the standard peripheral window (WORKER6); the spec; the decisions log.
- Provide the **standard peripheral window** (10) and a peripheral framework the replayer can be moved onto,
  but leave porting `Replayer.java` itself to WORKER6, unless it is needed to keep the build green.

WHAT TO BUILD, in this order (each phase ends with the suites passing, then a push)
1. **The packet path:** the 256-bit link word and its layout (2, 30); the 32-bit address with region and byte
   offset (5); the modes (6); four counters with the 3-bit field, additive arming, decrement K after the
   director with K by 32's formula (3, 30, 32); the mode-0 command trigger at port B (6); natural alignment
   and the bad-packet table (26, 32); no spanning (26); program memory load-only (5).
2. **Registers and events:** the controller block (11, with 7, 13, 30), `PARAMS`/`STATUS`/`ERRORS` (18), the
   pulses (8), `EVENTS` (16), `ROUTER_HDR`/`ROUTER_ADDR` with the no-increment bit (7), the common header
   block (12, 30), `PULSE_DMA` clearing DMA run done (17). Generate `mesh.h` with one struct per block (14).
3. **Peripherals:** up to three per tile (9); the standard window with counted and live events (10); the UART
   as C&C 1's peripheral, and C&C 1's registers (28, without `RESET`, 34); `ERROR_LINES`, READY with the
   expected mask, `PULSE_GO`, the one watchdog, the toast pin (35's toast pin replaces 24's error pin: build one hardware pin) and
   `LED` (15, 28, 35, 36).
4. **Errors, reset and boot:** terminal traps and the handler conventions (20); no HALT state (23); **the
   toast pin and the outside resets (35)**: model the toast pin, and hard and soft reset as simulation
   inputs (a test harness plays the outside world); the boot ROM, exactly as listed in 36, and the boot
   sequence (22, 31, 36). **C&C 1 stays a behavioural Java model** (as `CnC.java` in v1.1), driven by the test
   harness, which also plays the outside world: it lands C&C 1's state and resets the chip (36). 21 and 34
   are superseded except what 35 keeps; build no self-reset; 33's deferred items are out of scope.
5. **meshsim-only checks** (26, 27, 32): out of bounds, running past the end, reserved modes and counter codes,
   unaligned or spanning access, the reply and command conventions, invariant 11, `ecall`/`ebreak` and other
   traps with no `ERRORS` bit, writes to data memory word 0, credits returned to a full counter; and the
   stray diagnostic for unexpected arrival, with the error itself at the decrement (3). Replace `ebreak` as
   the way a test ends with the simulator-only exit word (36) before rewriting the suites.

RULES
- **The decisions log is the design.** When it is silent, ambiguous or wrong, don't invent: record a question
  in `WORKER4/QUESTIONS.md` (what, where, your proposed answer) and carry on with your proposal, marked in the
  code. The integrator collects the questions.
- Keep v1.1's suites where their meaning survives, rewritten to v1.2; retire those whose subject is gone
  (REPORT, HALT, the named counters, the sender), noting each in your report.
- This prompt is the go-ahead to change the files in your scope on `v1.2-meshsim`, and to write in
  `WORKER4/`. Change nothing else.
- Run `git pull --rebase` before every push. Keep `WORKER4/NOTES.md` as you go.
