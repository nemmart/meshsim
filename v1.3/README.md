# v1.3: the Tracer (frozen 2026-11-06)

> **For the RTL: start here.** v1.3 is the Tracer. Read **`spec/CHANGES-v1.26.1-to-v1.3.md`** first: what to build or change,
> unit by unit, each item marked whether it affects the RTL. Then **spec 4.21**, the Tracer (with 4.21.10, the segment's
> barriers and deliveries). The replayer is unchanged from v1.26.1. The spec makes reasonable default calls: where the RTL
> finds a better way, the spec follows it.

# mesh-sorter v1.1 (spec through part M, 2026-10-27; the milestone merge of the spec, simulator and replayer sessions)

A 64-tile mesh sorter: the hardware specification, its figures, a cycle-level simulator, the tile software (including a complete parallel sort), and the measurement kits.

| path | what |
|---|---|
| `Intro.pdf` | **start here:** how the mesh sorter sorts, a 13-page illustrated introduction for someone new to the project (source and figures in `intro/`) |
| `Reference.pdf` | the programmer's register reference: every register, field and rule, with worked examples (built from `sw/REGISTERS.md`) |
| `spec/` | **`machine-spec.md`**, the hardware, `replayer-opcodes.md`, the replayer's opcode semantics (normative for what each row computes), and `schedule.md`, the 16-group all-to-all schedule |
| `tools/replayer-opcodes/` | the harness, built against the jolt-cpp tracer, behind `spec/replayer-opcodes.md`'s tables and test vectors |

| `sw/` | `mesh.h` 1.1 (generated by meshsim), `CONVENTIONS.md` (the control conventions), `RECIPES.md` (tested code for every common operation), `REGISTERS.md` (the programmer's register reference) and `regdoc/` (its worked-example diagrams and PDF build) |

| `DEVIATIONS.md` | what deviates from the spec or is left undone in the code |

**Start here:** `Intro.pdf` for the ideas, then `Reference.pdf` to program the machine; then `spec/machine-spec.md` for the hardware, with `diagrams/` beside it; `sw/REGISTERS.md`, `sw/CONVENTIONS.md` and `sw/RECIPES.md` to program a tile; `meshsim/README.md` to run the simulator (`meshsim/run_tests.sh`); `kit/README.md` to measure the sort.

**Not rebuilt in this session:** `Intro.pdf`, `Reference.pdf` and the figures (they predate spec 26n; `make_docs.sh` rebuilds them).

**In brief:** on meshsim v1.1 (spec 26n), the sort orders 64 × 65,536 records (32-bit keys with 32- or 128-bit values) in about 0.9–1.4M cycles on uniform keys and up to about 2.0M on the most skewed data sets tested (`RESULTS-full-size.md`; v1.0's figures, 0.9–1.5M and 2.2M, are in `results/full-size/`). The spec's open items (section 13) are the questions left for the hardware.

**Planning notes:** `planning/PLANNING-NOTES-2026-10-27.md` collects this revision's status, measurements, rulings, the chip-level design not yet in the spec, open design discussions and the to-do list for the next revision.
