# WORKER18 report: the v1.35 inventory and porting plan

Branch `sim-w18` (documents only). The deliverable is `sim/planning/V135-INVENTORY.md`.

**What it holds.** Every capability of v1.3's Java meshsim, in groups A-J:
- A, the stand-alone tree's files;
- B, the chip;
- C, the suites;
- D, the sort and kit;
- E, the Tracer and replay;
- F, the input tools;
- G, the benches;
- H, the options and outputs;
- I, what in `sim/` needs Java or `sim/ref`;
- J, the docs.

Each row gives:
- the capability, and who uses it;
- the C++ equivalent today, with the evidence that it matches v1.3, or that it is a gap or unchecked;
- under D39, the port: its estimate, how it is checked against v1.3, and its dependencies.

The rows are grouped into eight worker-sized pieces, P1-P8, with P9 if Q1 says to port. They come with an order in three waves, a summary, and eight questions for the owner.

**Measured, not assumed.** `sim/` was built without `ref/` (clang release). The build passes, and 48 of its 63 test binaries pass. The other 15 fail only on data files read from `ref/` (hops, boot ROM, riscv-tests images, tables, opcode table, vectors), and all 63 pass with `ref/` restored (I1). Every conformance fixture is committed: only the regenerators and `make conformance` need a JDK (I3).

**Main findings.**
- The firmware sources exist only in `sim/ref`, and `mesh.h` is generated by Java (A6-A11).
- The sort has been compared only on uniform k128 (D2).
- No user-facing outputs exist: no PhaseLog CSVs, sort CSVs or acceptance results (H3, D1, E5).
- There is no invariant checker (B19) and no reset path (B20).
- Most of `run_tests.sh`'s suites have no C++ counterpart beyond the units' conformance scripts (C).

**Open:** Q1-Q8 in the inventory. The largest are Q1 (whether gold and jumpmap are ported) and Q2 (whether Python is allowed as a prerequisite).
