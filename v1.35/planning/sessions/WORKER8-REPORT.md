# WORKER8 report: G1 (the tile's control) and the fingerprint's C++ side

For W11 (G3) and W12 (G4), who extend what is here. Details and the dated history are in `NOTES.md` beside this file;
the specification is `sim/tests/AUDIT-M2.md` (1.2, 2, 3.3-3.7, 5, 6; 2.5 and 3.3 corrected by D27). Everything below is
on main at 37e28a8 or later, make check clean.

## 1. What G1 built, and how it is checked

**Units** (`sim/src/units/`), added for tile k by `add_g1` (`tile_ctl.cpp`), a `ControlBuilder` that W9's tile builder
calls (chip.h's `ControlIO` is the contract):

| unit | file | what it is |
|---|---|---|
| `t<k>.core` `TileCore` | `tile_ctl.h` | W5's `Rv32` with M2's ports: port B applied before its step, the send `Hold` (refused: re-put next cycle, the core stalls), table-window stores (`tables`, `hist_w`), one-cycle HIST loads (`hist` RegFile) |
| `t<k>.ctl` `TileCtl` | `tile_ctl.h`, state in `regblock.h` | the register block: `RegBlockState::end_cycle(t)` runs at level 0 of t + 1 (the shifted end of cycle, PORTS.md 7) from what reached it; the view as a `RegFile`; `dma` RegFile; READY and the error line on `line` |
| `t<k>.dir` `Director` | `director.h` | the only path into the tile: one packet a cycle off the eject link, switched by mode (section 4) |
| `t<k>.we`, `.ag`, `.gather`, `.ts`, `.hist` | `write_engine.h`, `ag.h`, `gather.h`, `table_store.h` | configuration parts of G3's and G4's units (section 2) |

`RegBlockState` (plain logic, shared with W5's M1 `RegBlock`) holds TileControl's state in full:
- the send registers;
- the write counters, with the director's due decrement judged before the core's same-cycle store (D27);
- the counter events and qualifiers, and the done gate;
- DMA_CONFIG and the record base;
- SRAM_RD_DEST_ADDR;
- the conditions;
- STATUS;
- READY and the error line.

Internal latencies (approved): port B and command landed `Link(cm_latency + 1)`; the K-line `Link(K + 1)` of counter ids
from the director to the block (no wake at the due cycle); the core's bus and window stores `Link(1)`.

**Checks** (all in make check):
- `test_statefp_core`: the core, its memories and the block against ref every cycle on all 67 M1 goldens. It runs both through W5's direct driver and on the engine (ready-driven and step-all). The reference streams come from `tests/ref/CoreFp.java`, into `tests/fp-m1/`, regenerated by `regen.sh [--check]`.
- `test_g1_replay`: tile 0's G1 units against golden-m2, every unit every cycle, on wfi to its end and on regs through the limit (section 5). It replays ref's G1 boundary (`tests/ref/G1Trace.java` into `tests/g1-replay/`, with `regen.sh`). It also checks `units::line_edge` against the real line every cycle. It runs under four option sets.
- W9's `test_chip`: the whole chip with these units in every tile matches golden-m2 the same way, also split over threads.
- Unit tests: `test_core_m2`, `test_g1_tile`, `test_regblock`, `test_statefp`, `test_statefp_g1`.

## 2. The configuration parts, and how to extend them

The owner's ruling: each is the **start of the real unit, in that unit's own file**, headed "configuration part by W8
(G1); G3/G4 extend this file". Extend the same struct; don't replace it with a new one.

- **The configuration is never copied.** The block exports `dma`, a 2-register `RegFile` (`DMA_R_CONFIG`,
  `DMA_R_RECORD_BASE`, as TileControl holds them). Each engine declares `sim::RegFileIn dma` and derives its fields when
  it steps (`WriteEngine::bucket_digit/hist_digit/augment_base`, `AddrGen::kind/run_start/run_count`,
  `Gather::k/base`; the `mc_*` field helpers are in `write_engine.h`). ref: setMasterConfig/setRecordBase at endCycle(t),
  used from t + 1; reading the block's RegFile at a later level gives exactly that.
- **`WriteEngine`** (G3): `FifoIn in` (we-in, depth `we_in_depth`), `dma`. Its step is fatal on any arrival, "not
  modelled in M2 yet (G3)". That is where you start: modes 0 (region 0x03) and 1, the pointer stage, PTR's
  read-modify-write, the SRAM write hold.
- **`AddrGen`** (G4): `dma` only. Its start pulse is still to come. **PULSE_DMA is fatal** twice over: in the core's
  register access table (`regmap.h`, A_OUT) and in the block's `apply` ("not modelled in M2 yet (G4)"); lift both.
  SRAM_RD_ADDR_QUEUE (the read port, G3) is A_OUT in `regmap.h` too.
  The pulse should be a Wire written by the block at level 0 of t + 1 (`TileCtl::step`), so the AG acts at t + 1 as
  in ref. The AG's and gather's status come back as Regs into the block (`RegBlockState::In`; STATUS bits 0-2,
  EVENTS [10] via `rd_done_prev`, which stays false until then).
- **`Gather`** (G4): `FifoIn in` (depth `gather_depth`), `dma`; fatal on any arrival.
- **`TableStore`, `HistStore`** (G3): the memories (`TableMems`, `HistMem`) with incremental `MemSum`s, written by the
  core's window stores (`Link(1)`, `{table << 32 | index, value}`, already masked; applied in the store's step at
  t + 1, before t + 1's readers). `HistStore` exports HIST as a 256-register RegFile for the core's one-cycle loads.
  Still to add: the request FIFOs and returns, PTR's and HIST's RMW pipes with their bypass, and a controller access
  lost to a same-cycle write-back (ref's ctrlWrite/ctrlRead). Keep the RegFile current with every write-back.

## 3. Plugging a unit into the fingerprint library

The library is `tests/statefp.h/.cpp`. G1's writers are in `tests/statefp_g1.h/.cpp`.

A unit's stream is ref's `StateFp.java` stream for that unit, **word for word**. Write it as a function
`void(const void* obj, fp::FpOut& o, const fp::FpCtx& x)` and register it under its `.fp` name:

```cpp
// tests/statefp_g3.cpp (example: the read port, replacing W8's stub)
void w_rdport(const void* p, fp::FpOut& o, const fp::FpCtx& x) {
    const units::ReadPort& u = *static_cast<const units::ReadPort*>(p);
    o.w("inUse", u.in_use);                 // names as StateFp's, for fpdump diffs; only dumped, never hashed
    o.w("outstanding", u.outstanding);
}
reg.add("t" + std::to_string(k) + ".rdport", w_rdport, &sim.unit<units::ReadPort>("t" + std::to_string(k) + ".rdport"));
```

- **Stubs to replace.** `register_g1` registers stubs for `sram`, `sram.data` and `rdport` (G3). Take them out of
  `register_g1` in the same commit that registers yours; a second writer for a name is fatal.
- **Buses.** Use `fp::link / fifo / hold` (`statefp.h`), with entries read through the port observer
  (`x.sim->observe(port, buf, max)`; the machine built with `Options::observe_arrivals`).
- **The shifted end of cycle.** Any input whose latency carries the +1 of the shifted end of cycle needs this treatment:
  - an entry arriving at c + 1 has already been applied by ref at c, so apply it to a copy;
  - list later entries with arrival − 1;
  - see `block_end`, `memories`, `w_ts`, and `units::block_at_end` (`tile_ctl.h`), which W9's C&C writers share.
- **Finding the named word.** Compare per point with `FpGolden::load` / `compare` to get the first differing cycle and
  unit. Then dump both sides: `FpRegistry::dump` here, `M2Prog ... fpdump=C:UNIT dumpto=F` in ref. Diffing the dumps
  names the word.
- **The memory-sum rule (owner).** Keep a memory's sum incrementally (`units::MemSum`, `src/units/memsum.h`: two fmix
  and an add per write) **only where a scan at fingerprint time is too slow**. That means big SRAM (G3); the table
  memories already do. The controller memories are scanned (2 × 8 K words, ~30 µs).

## 4. The director's switch for modes 2-4

`Director::step` (`director.h`) takes one packet a cycle and switches it as ref does:
- bad packets become an event to the block;
- size 11 is dropped;
- a misaligned mode 0, or modes 6-7, is fatal (UB);
- counted modes put their counter id on the K-line.

| mode | where | state |
|---|---|---|
| 0, region 0x00/0x01 | port B into the core (+ command landed for slot 0) | G1, done |
| 0, region 0x03 | `we_in` Fifo -> `WriteEngine` | G3 |
| 1 | `we_in` | G3 |
| 2, 3 | `we_in` (the same path ref uses) | G4 |
| 4 | `gather` Fifo -> `Gather` | G4 |
| 5 | counted only | G1, done |
| 0, peripheral regions | fatal, not modelled in M2 | |

The switch is complete. Modes 2-4 already reach their engines' inputs, and the engines fatal until they're built, so
G4 needs nothing in the director. G3 adds the read port's couplings: a read-port result (`read_port_tag`) is fatal in the
director today, and the overlap check and `acceptedAt` are G3's.

## 5. The regs limit: `fp::kRegsCheckedThrough` (824)

regs's mode-1 self-sends reach the write engine at 825. The write engine is fatal until G3 lands that path, so every
regs check stops at this named constant (`tests/statefp_g1.h`). It is used in `test_g1_replay`, W9's `test_chip`
(`run_all` and `chip_every_tile_when_asked`) and `test_statefp_g1`.

**To lift it:** in the commit that lands mode 1 through the write engine, PTR's RMW and big SRAM's writes, make the
three tests check regs to the golden's end, then delete the constant.
- `test_g1_replay` also needs its stand-in to cover what crosses tile 0's boundary after 825. `G1Trace` already records
  it to regs's end; regenerate with `tests/g1-replay/regen.sh`.
- `test_statefp_g1`'s check at the limit lists the configuration parts; after G3 those units have real state, so the
  check moves to the real writers.

## 6. ERRORS: conditions are events (PORTS.md 8, D29)

A condition that sets ERRORS in ref's cycle must step the block **as an event** (a width-0 `Link(1)` into the block), not
as a Count the block reads at its next step: the block runs only when something reaches it.

| condition | how it reaches the block |
|---|---|
| BAD | `Director::bad` -> `TileCtl::bad` |
| ROUTER_OVF | W9's `ControlIO::router_ovf_ev` -> `TileCtl::ovf` (counted at t + 1, D28) |
| UNEXPECTED | arises in the block (the K-line's event) |
| DONE_EARLY | arises in the block (a store) |
| BUS_ERROR, ILLEGAL | the core's bus |

Still to do:
- **G3** owns WE_IN_OVF, TABLE_OVF and READ_PORT.
- **G4** owns GATHER_OVF and DRIFT.
- Today the we-in and gather overflows are framework `count_overflows` Counts, read only as statistics. The unit that
  counts an overflow (at t + 1, D28) must also put an event.
- To add one: a new `In` flag in `RegBlockState`, setting its `conditions` bit in `end_cycle`; a width-0 `LinkIn` in
  `TileCtl` (take it in `step`, and read it in `block_at_end` for the fingerprint); the wiring in `add_g1`.
- Test it alone, as `test_g1_tile` does for BAD and ROUTER_OVF: the bit set at the end of the cycle ref sets it, with
  nothing else arriving.

## 7. Unfinished, or worth knowing

- **ref's order, not the spec's:** `pendingAdd` is always 0 in ref's run, because the director steps before the core.
  The C++ judges a due decrement without the core's same-cycle store (D27). AUDIT-M2 2.5 and 3.3 were corrected.
- **Not modelled here** (all fatal, named):
  - REQUEST_* in M2 (AUDIT-M2 1.2 (C));
  - peripheral windows;
  - PULSE_DMA;
  - SRAM_RD_ADDR_QUEUE;
  - HIST/PTR window stores lost to a write-back (G3);
  - the read port.
- **The FIFO overflow Counts are not seen in the fingerprint.** `block_at_end` passes them as unchanged, because their
  ref timing is D28's. Once they are events, read them there like `bad`.
- **The M1 bench** (`controller.h`'s `Core`/`RegBlock`, `TestBench`) is unchanged for M1's goldens. An M2-only
  environment hook missing from it (send, table window, HIST) stops with a FATAL naming what the bench lacks.
- **The reference tooling** under `sim/tests/ref/` (`CoreFp.java`, `G1Trace.java`) and the two `regen.sh` scripts
  build ref in a scratch copy, as golden-m2's does. They need a JDK.
