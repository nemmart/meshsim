# Worker 19 (sim/, v1.35, P1): the stand-alone tree

**The project.** meshsim is the simulator for a parallel compute mesh (part of an ASIC for proving the Jolt zkVM).
**meshsim v1.35 is its C++ implementation in `sim/`** (D37), exact against v1.3's Java (kept as the oracle in
`sim/ref/`) and much faster: the controller's programs, the full-size sort (20.9×), and v1.3's segment test T2 on all 128
segments of both workloads (6.5×). **v1.35 is being frozen** (D38-D41, `sim/planning/PLAN-V135.md`): **the simulator
and everything that runs it off Java, every capability of v1.3's Java meshsim with an equivalent, and v1.35 a
stand-alone directory with all the source needed to build and run everything**; the offline input tools (`gold`,
jumpmap, KeyGen, SplitSets, ConvertDelivery, SyntheticDelivery) stay Java in v1.35's own `pipeline/` folder. W18's
inventory (`sim/planning/V135-INVENTORY.md`) is the porting plan: rows by capability, pieces P1-P8, waves.

**You are P1** (inventory rows A1-A13, I1-I3, I5's `bench/` scripts, C26): make `sim/` stand-alone, so nothing in it reads `sim/ref` or needs Java to build, test or run the simulator, and give the Java that stays its own home. P1 is small and unblocks every later "nothing reads `ref`" check; W20 (P2) and W21 (P7a) work beside you.

THE WORK
1. **The data files** (hops.txt, bootrom.hex, the riscv-tests images, the replayer tables, opcode_table.txt,
   vec-821e1bd.tsv, and any other file the C++ reads from `ref/`): copies committed into `sim/`, with a manifest of their
   hashes against `sim/ref`; every reader repointed. `make check` must pass in a copy of `sim/` with no `ref/`.
2. **The firmware sources and builds**: every C and assembly source the images come from (the tile programs, cc1/cc23,
   replay_ctl, tracer_ctl, the sort program, crt0.S, app.ld, bootrom.S, the recipes' sources), committed into `sim/`,
   with build scripts that need no `ref/`; the prebuilt images stay committed (the runner has no riscv toolchain), and
   a `--check` rebuilds them byte-identical to v1.3's where the toolchain exists.
3. **The `mesh.h` generator** (today generated by `Registers.java`): a non-Java generator (C++ or shell), producing
   `mesh.h` and REGISTERS.md's tables byte-identical to v1.3's.
4. **`pipeline/`**: the Java that stays (D40): `gold`, jumpmap, `inputs/`, KeyGen, SplitSets, ConvertDelivery,
   SyntheticDelivery, with what they need from v1.3, self-contained with its own build (a JDK as its only prerequisite),
   nothing in it read by the simulator's build or tests. Check each tool builds and runs there.
5. **`sim/oracle/`** (D41 Q8): everything that needs Java or `sim/ref` (the `--check` regenerators, `make conformance`,
   the golden regeneration scripts, the Java drivers in `tests/ref/`, the Quest task makers that embed `ref`) moved there,
   still working from its new place, and excluded at the freeze.
6. **The proof**: a copy of `sim/` without `ref/` and `oracle/` builds and passes `make check` on both compilers, and
   `pipeline/` builds alone.

RULES
- **Propose your plan first** in your `NOTES.md` and wait for the go-ahead before writing code.
- Work on your own branch; merge `main` in often (never rebase); the integrator merges into `main`. Keep notes, questions
  and report in your session folder.
- `sim/ref` is frozen (D5). Exactness is the requirement: a difference from a reference is a bug, never a tolerance; if
  you believe a reference is wrong, stop and report it with the evidence.
- The cycle-loop rules (D6, D24): no STL, no allocation, no virtual calls in any `step` or engine path, diagnostics
  included; untyped 64-bit words; three-word link words (D17). Sanitizers and deterministic tests from the first commit;
  `make check` clean on gcc and clang (run it build by build if the tool limit bites). Every new unit passes the debug
  checks: shuffle, both orders, step-all, the missed-wake detector.
- Long runs and all timing go to the runner. **Quest numbers:** pull Quest and re-read `NUMBERS.md` immediately before
  claiming, push the claim before writing the task. Tasks carry embedded kits. **No machine-specific values** (D21): CPU
  lists from `sim/tools/machine.sh`, every result with its machine. Background jobs don't survive a turn.
- Never write a token into a file. Never `pkill -f`; use `pgrep` and kill by PID.
- Commit and push after each completed piece, keep the last tool calls for committing, end each turn with a clean
  `git status`.
- Keep replies to the owner short.
- Branch `sim-w19`. You'll touch many files' paths: keep each commit mechanical and say what moved, so W20's and
  W21's merges stay easy; tell the integrator before moving anything they're editing. Exactness: every moved or
  generated file byte-identical to v1.3's, or the difference explained.

DELIVERABLES: the stand-alone tree, `pipeline/` and `sim/oracle/`, proven by a build and `make check` without `ref/`;
