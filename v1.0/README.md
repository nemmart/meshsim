# mesh-sorter v1.0

A 64-tile mesh sorter: the hardware specification, its figures, a cycle-level simulator, the tile software (including a complete parallel sort), and the measurement kits.

| path | what |
|---|---|
| `Intro.pdf` | **start here:** how the mesh sorter sorts, a 13-page illustrated introduction for someone new to the project (source and figures in `intro/`) |
| `Reference.pdf` | the programmer's register reference: every register, field and rule, with worked examples (built from `sw/REGISTERS.md`) |
| `spec/` | **`machine-spec.md`**, the hardware (v1.0), and `schedule.md`, the 16-group all-to-all schedule |
| `diagrams/` | the figure set: 29 figures in eight parts, from the system down to RTL: `svg/` the figures, `png/` renderings, `src/` the generators (`diagrams/README.md` is the index) |
| `sw/` | `mesh.h` 1.0 (generated by meshsim), `CONVENTIONS.md` (the control conventions), `RECIPES.md` (tested code for every common operation), `REGISTERS.md` (the programmer's register reference) and `regdoc/` (its worked-example diagrams and PDF build) |
| `meshsim/` | the cycle-level simulator: source, tests, the tile programs' build, and `results/`, the logs of its last full `run_tests.sh` |
| `sort/` | `program/` (the sort), `split/` (the split, with `BINDING.md`), `skew/` (the skew planner, with its regression harness) |
| `kit/` | the measurement kit (`kit/README.md`): the whole sort at 64 × 65,536 on every data set in both formats, Java only |
| `verify-v1.0/` | the verification kit: the previous build against v1.0, phase by phase |
| `results/` | the measured results (`results/README.md`); `results/build/` holds the measurements made while building v1.0 |
| `BUILDING.md`, `make_docs.sh` | what builds what, and one command to rebuild every figure and both PDFs |
| `DEVIATIONS.md` | what deviates from the spec or is left undone in the code |

**Start here:** `Intro.pdf` for the ideas, then `Reference.pdf` to program the machine; then `spec/machine-spec.md` for the hardware, with `diagrams/` beside it; `sw/REGISTERS.md`, `sw/CONVENTIONS.md` and `sw/RECIPES.md` to program a tile; `meshsim/README.md` to run the simulator (`meshsim/run_tests.sh`); `kit/README.md` to measure the sort.

**In brief:** the sort orders 64 × 65,536 records (32-bit keys with 32- or 128-bit values) in about 0.9–1.5M cycles on uniform keys and up to about 2.2M on the most skewed data sets tested, on the simulator (`results/`). The spec's open items (section 13) are the questions left for the hardware.
